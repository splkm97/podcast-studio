# 팟캐스트 자료 수집

## 우선순위

1. **사용자가 준 자료가 기준이다.** 주제의 범위와 관점은 여기서 정해진다. 전부 읽는다
2. **검색은 빈틈만 채운다.** 사용자 자료가 다루지 않는 정의, 배경, 최신 상태(버전, 지원 종료 여부 등)만 찾는다. 사용자 자료와 충돌하는 최신 정보가 나오면 둘 다 기록하고 충돌을 표시한다
3. **1차 출처를 우선한다.** 공식 문서, 릴리스 노트, 프로젝트 저장소, 원 논문. 요약 블로그는 1차 출처를 찾는 길잡이로만 쓴다

사용자 자료가 없으면 검색으로만 진행하되, 출처를 최소 3개 이상 서로 다른 곳에서 확보한다.

## 산출물

`sources.json` — 출처 하나당 한 항목.

```json
[{"id": "src1", "title": "…", "url": "https://…", "kind": "user"},
 {"id": "src2", "title": "…", "path": "docs/…", "kind": "user"},
 {"id": "src3", "title": "…", "url": "https://…", "kind": "search"}]
```

`research.md` — 대본 작가가 이것만 보고 쓸 수 있게.

- 맨 위에 주제 범위 한 단락: 이번 회차가 다루는 것과 다루지 않는 것
- 사실은 한 줄에 하나, 끝에 근거 출처 id: `- etcd 스냅샷은 … 한다 [src1, src3]`
- 출처마다 다른 주장은 `충돌:` 줄로 남긴다
- 청취자가 낯설어할 약어와 원래 이름 목록 (대본의 약어 풀이에 쓰인다)
- 출처 문장을 길게 옮기지 않는다. 자기 말로 요약하고, 꼭 필요한 인용만 짧게 둔다. 대본으로 넘어가는 문장이 원문을 베끼지 않게 하려는 것이다

## 게이트

`python3 -m tools.check_links episodes/<id>` 로 모든 출처가 살아 있는지 확인한다. 실패하면 오케스트레이터의 재시도 규칙을 따른다.
