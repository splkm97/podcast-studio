# 영어 기술 용어 → 한글 음차 (팟캐스트 대본용)

## 목적

대본은 **읽히는 글이 아니라 들리는 글**이다. 진행자나 TTS가 그대로 읽었을 때 한국 엔지니어 청취자가 "아, 그거" 하고 바로 알아듣는 표기가 정답이다. 그래서 국립국어원 규범보다 **현업 회의·컨퍼런스 발표에서 실제로 쓰는 발음**을 따른다.

- 규범: 메시지, 아키텍처 / 관용: 메시지, 아키텍처 → 둘이 같으면 그대로
- 규범과 관용이 갈리면 관용: `Redis` → 레디스, `nginx` → 엔진엑스

## 출력 규칙

- 대본 본문은 **한글만** 쓴다. 영어 병기·괄호 설명을 넣지 않는다.
- 음차하지 않는 것: 이미 한국어인 단어, 원문이 번역어로 쓴 단어(배포, 장애 등). **번역은 이 스킬의 일이 아니다.** 영어로 적힌 것만 소리대로 옮긴다.
- 내용을 덧붙이거나 빼지 않는다. 약어 풀이 같은 설명 추가는 대본 단계(podcast-script)의 일이다.
- 판단 근거가 약했던 단어는 단독 사용 시 본문 밖 확인 목록으로, 파이프라인에서는 해당 segment의 `tts_notes`에 남긴다. 확인은 사람이 아니라 STT 역검증이 한다.

## 판단 순서

단어마다 아래를 위에서부터 적용하고, 처음 걸리는 규칙을 쓴다.

### 1. 맥락으로 정체부터 확정

같은 철자라도 뜻이 다르면 발음이 다르다. 앞뒤 문장으로 무엇을 가리키는지 먼저 정한다.

- `Go`: 언어면 **고** (고랭이라고도 하지만 대본에선 "고 언어"처럼 풀어주는 편이 들을 때 명확)
- `Pod`: 쿠버네티스 맥락이면 **파드**, 오디오 기기면 팟
- `Helm`, `Spring`, `Rust`, `Swift`, `Node`: 기술 맥락에서는 제품·언어명으로 읽는다
- `char`: 타입이면 **차**, 문자 일반이면 캐릭터
- 맥락으로도 확정이 안 되면 대본 주제에서 가장 흔한 쪽을 택하고 확인 목록에 올린다

### 2. 공식 한국어 표기가 있으면 그것

회사가 한국 시장에서 쓰는 이름이 있으면 우선한다. `Azure` → 애저, `Microsoft` → 마이크로소프트, `Amazon Web Services` → 아마존 웹 서비스.

### 3. 약어는 "읽는 방식"을 먼저 가른다

- **철자로 읽는 약어**: 알파벳 이름을 이어 쓴다. `API` → 에이피아이, `CPU` → 씨피유, `GPU` → 지피유, `CI/CD` → 씨아이씨디, `gRPC` → 지알피씨, `AWS` → 에이더블유에스
- **단어처럼 읽는 약어**: 현업에서 굳은 발음을 쓴다. `YAML` → 야믈, `JSON` → 제이슨, `SaaS` → 사스, `PaaS` → 파스, `OAuth` → 오어스, `NAT` → 낫, `RAM` → 램, `LAN` → 랜
- 둘 다 쓰이는 경우(`SQL`: 에스큐엘/시퀄)는 한국 현업 다수 쪽(에스큐엘)을 기본으로 한다
- 알파벳 이름 표기 통일: A 에이, B 비, C 씨, D 디, E 이, F 에프, G 지, H 에이치, I 아이, J 제이, K 케이, L 엘, M 엠, N 엔, O 오, P 피, Q 큐, R 알, S 에스, T 티, U 유, V 브이, W 더블유, X 엑스, Y 와이, Z 지

### 4. 줄임 표기는 원래 이름으로 읽는다

듣는 사람은 철자를 못 본다. 숫자 줄임은 원형으로 풀어서 읽는다.
`k8s` → 쿠버네티스, `i18n` → 인터내셔널라이제이션, `a11y` → 접근성이 아니라 어세서빌리티. 원형이 너무 길어 대본 흐름을 끊으면 확인 목록에 올려 사람이 고르게 한다.

### 5. 합성어·명령어는 조각 단위로

조각마다 관용 발음을 붙인다. 붙여 쓸지 띄어 쓸지는 현업에서 한 단어로 인식되는지로 정한다.

- `kubectl` → 큐브컨트롤 (큐브씨티엘도 쓰이지만 대본 안에서는 하나로 고정)
- `etcd` → 엣시디, `systemd` → 시스템디, `containerd` → 컨테이너디
- `OpenStack` → 오픈스택, `GitHub` → 깃허브, `PostgreSQL` → 포스트그레스

### 6. 나머지 일반 단어는 관용 발음

`cache` → 캐시, `queue` → 큐, `proxy` → 프록시, `latency` → 레이턴시, `throughput` → 스루풋, `sidecar` → 사이드카.

## 숫자·기호·단위

TTS가 엉뚱하게 읽기 쉬운 부분이다. 특히 CLOVA Voice는 **기호와 괄호 안 텍스트를 읽지 않으므로**, tts 텍스트에는 괄호·슬래시 같은 기호를 남기지 않는다. 읽어야 할 내용이면 말로 풀어 쓴다.

- 버전: `v1.29` → 버전 일 점 이십구. 메이저만 중요하면 맥락상 "일 점 이십구 버전"도 가능
- 단위: `GB` → 기가바이트, `ms` → 밀리초, `vCPU` → 브이씨피유, `QPS` → 큐피에스
- 기호: `/`는 읽지 않거나 맥락상 "와" "슬래시"로, `.yaml` 같은 확장자는 닷 야믈
- 쉼표: tts에는 쉼표를 쓰지 않는다. TTS가 쉼표를 쉼으로 처리하지 않고 무시하기 때문이다. 일반 문장의 쉼표는 띄어쓰기로 바꾼다. 나열된 항목 사이의 쉼표는 "와/과", "그리고"로 바꾼다. 쉼표만 지우면 붙어 있는 약어를 STT가 한 단어로 합쳐 적는다 (예: "씨에이, 케이엠에스" → "씨에이와 케이엠에스"). 자막인 `src`의 쉼표는 그대로 둔다
- 정수는 그대로 둬도 되지만, 소수점이 들어간 숫자와 버전은 반드시 풀어 쓴다 (린트 게이트가 걸러낸다)

## 조사 재조정

음차 후 받침이 바뀌면 뒤 조사도 고친다. 원문 작성자가 영어 발음 기준으로 붙인 조사가 한글 표기와 어긋나는 일이 흔하다.

- `Kafka를` → 카프카를 (그대로), `etcd가` → 엣시디가
- `SQL을` → 에스큐엘을, `Redis는` → 레디스는
- `API를` → 에이피아이를
- 받침 유무를 음차 결과 기준으로 다시 확인한다

## 일관성

대본 하나 안에서 같은 단어는 처음 정한 표기로 끝까지 간다. 긴 대본은 처음 훑을 때 등장 용어를 먼저 모아 표기를 정한 뒤 본문을 바꾼다.

## 참고 사전

표기 사전은 두 개다.
- `references/glossary-learned.md`: STT 역검증으로 고쳐진 표기. **가장 우선**한다
- `references/glossary.md`: 기본 표기

둘 다 `- 영어 = 한글` 한 줄 형식이고, 파이프라인 스크립트가 이 형식을 파싱하니 지킨다. 맥락(1번)은 사전보다 우선한다. 사전에 없는 단어는 판단 순서로 정한다.

## 예시

**입력**
> 오늘은 k8s에서 etcd 백업을 어떻게 자동화하는지, 그리고 Helm chart로 Velero를 올릴 때 YAML에서 주의할 점을 얘기해 볼게요. kubectl 한 줄이면 되는 줄 아셨죠?

**출력**
> 오늘은 쿠버네티스에서 이티씨디 백업을 어떻게 자동화하는지 그리고 헬름 차트로 벨레로를 올릴 때 야믈에서 주의할 점을 얘기해 볼게요. 큐브컨트롤 한 줄이면 되는 줄 아셨죠?

## 파이프라인 모드 (script.json)

podcast-orchestrator가 부를 때는 회차 폴더의 `script.json`을 다룬다.

1. 모든 segment의 `src`를 먼저 훑어 등장 용어의 표기를 한 번에 정한다 (일관성)
2. segment마다 `src`를 음차해 `tts`에 쓴다. **문장 수와 순서를 바꾸지 않는다.** 자막은 `src`, 음성은 `tts`라서 둘이 같은 말을 해야 한다
3. 확신이 낮은 표기는 그 segment의 `tts_notes`에 `"원문 → 표기: 이유"`로 남긴다
4. tts에서 쉼표를 없앤다 (숫자·기호·단위 절의 쉼표 규칙)
5. 끝나면 `python3 -m tools.lint_script episodes/<id>`로 라틴 문자·기호·소수점 잔여를 확인하고, 걸린 segment만 고친다
